## 背景与边界

owner 的原话：「把上传图片变成一次性上传多少张，虽然也是按顺序做，但上传起来方便很多」。

需求是**省人工操作**，不是省钱也不是提速：10 张仍然是 10 次 LLM 调用，成本线性。
这一点要在 UI 上让用户有感知，但不要写成吓人的警告。

**实现路线定死：客户端按顺序循环调用现有的单张接口。**
`server/` 一行不改，不新增批量端点。理由是现有单张链路（上传 → 感知 → 提议）已经真机验收过，
批量只是把"人点 N 次"变成"程序点 N 次"，没有任何服务端语义需要变。
省下来的复杂度用在下面第 2 节那个真问题上。

## Goal

### 1. 多选与顺序

- `app/app/(tabs)/index.tsx` 的 `launchImageLibraryAsync` 去掉 `selectionLimit: 1`，改为上限 **20**
- **严格按用户选择顺序处理，不重排、不并发**。聊天截图有时间语义，
  后面的截图可能修正前面的事实（"我上个月跳槽去了翎点科技"），乱序会让归并结果不稳定
- `app/src/upload-draft.ts` 的 `asset: UploadImageAsset | null` 改为 `assets: UploadImageAsset[]`，
  reducer 相应支持增删与重置。`note` 保持整批共用一条（不做每张单独备注）

### 2. 批次内人物归并（本批最难的一处，先读完再动手）

**问题**：`resolveParticipants({ extraction, contacts })` 的 `contacts` 是**已入库**的联系人
（见 `shared/core/agent/resolve.ts:52`）。而行动卡片要人工确认后才写库。
所以批量处理时，第 1 张截图里的张三还停在待确认卡片中、没进数据库，
第 2 张截图再遇到张三，查库查不到，又判 `new` —— 同一个人会生成 N 张重复的 `create_contact` 卡片。

单张模式下这个问题不存在，因为用户确认完一张才传下一张。**是批量把它放大出来的。**

**解法**（不改 `resolve.ts` 本身，只改调用侧传什么）：

- 维护一个批次内的"待建联系人"表，每个分配一个**负数临时 id**（`-1`、`-2`…）
- 处理第 N 张时，传给 `resolveParticipants` 的 `contacts` = 已入库联系人 + 批次内待建联系人
- resolve 判出 `same_as` 且 `contact_id < 0` 时，说明命中的是本批次前面某张截图的待建联系人：
  不再生成新的 `create_contact`，而是把这张截图的证据挂到那张已有卡片上
- 执行阶段把负数 id 映射成真实数据库 id。**映射失败必须报错，不许静默丢弃证据**

`resolve.ts` 的 `ResolvableContact.id` 是 `number`，负数天然可用，不需要改类型。
但要在传入前确认负数 id 不会被其他逻辑当成真实主键使用——**动手前先 grep 一遍 `contact_id` 的所有消费点**。

### 3. 失败不中断整批

- 单张失败（OCR 抛错、LLM 报错、网络断）→ 记录该张的失败原因，**继续处理下一张**
- 整批结束后给汇总：成功 N 张、失败 M 张，失败的列出文件名与原因，提供"只重试失败的"入口
- 一张都没成功时，才把整批标记为失败

### 4. 进度可见

- 处理中显示「正在处理第 3/10 张…」，每张完成后推进
- 沿用 M4 那套两段式文案的思路，但要带上真实的序号，不要只是定时切换文案
- 整批预计耗时可以粗估后显示（OCR 路径每张秒级 + 一次文本 LLM 往返），
  拿不准就只显示序号，**不要显示编造的百分比**

### 5. 结果按截图分组

`app/src/flow-context.tsx` 目前是单 screenshot 状态机
（`screenshotId: number | null`、`cards`、`screenshotDetail` 全是单数）。
改成能承载一个批次：

- 保留"当前查看哪一张"的概念，新增批次列表与逐张状态（待处理 / 处理中 / 成功 / 失败）
- 审核页要能看出每张卡片来自哪张截图——`source_quote` 的可追溯性是产品承诺，
  批量之后更要守住，不能把 10 张的卡片糊成一个无源列表
- 合并后的联系人卡片（第 2 节那种）要能显示它聚合了哪几张截图的证据

### 6. 数量与成本提示

选中 N 张后，在提交按钮附近显示一行中性说明：处理 N 张、每张需要一次模型调用。
不要用警告色，不要吓人——用户是自己付费的 BYOK 用户，知情即可。
