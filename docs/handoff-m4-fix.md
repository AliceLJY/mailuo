# M4-fix：真机用户测试（UAT）反馈四项

## 背景
用户在 OPPO 真机做了第一轮完整体验，owner 复核后确认四项改进，全部有截图或复现证据。这是发布前最后一批代码改动。**自验用本机 Node 26。**

## Goal（四项，按序做）

**A. 时间解析：三行锚点升级为 14 天日期速查表**
复现证据：现有日历锚点已明确写"下周三是 09-02"并叮嘱"用锚点别自己算"，qwen 仍输出 `2026-08-26`（本周三）——模型不服从推理指令，疑似抓取锚点中第一个日期。CLI 复现：`extract fixtures/screenshot-1.png` 稳定返回 08-26。
修复：`prompts.ts` 的 calendar anchor 函数改为输出**从今天起未来 14 天的逐日速查表**，每行格式如 `2026-09-02 = 星期三（下周三）`——今天标"（今天）"、明天标"（明天）"、本周/下周的每个工作日都带中文相对称谓标注。指令改为"time_iso 的日期必须从下表中选取，禁止自行推算日期"。查表填空替代日历推理。
单测：断言锚点文本含 14 行日期、含"（今天）"标注、含正确的下周三日期（用固定 now 注入测试，勿用真实时钟）。真调复验由 owner 做。

**B. 全 app 扫除面向用户文案里的工程黑话**
真机截图证据：上传页"上传成功后初始化 flow，并跳到 /review/[id]"、日程页副标题"按 API 返回顺序展示标题、时间原文、解析时间…"——路由路径、flow、API 这些词是给工程师看的，不该出现在用户界面。
修复：全 app 扫一遍所有用户可见字符串（包括各页副标题、说明卡、loading、错误 toast），改成普通用户能懂的话（例：上传页那句改为"上传成功后会直接进入卡片确认页"；日程页副标题改为"即将到来的会议都在这里"）。**交付时贴一张「改动前 → 改动后」的文案对照表**，owner 按表验收。
判据：用户可见文案中不出现路由路径（/xxx/[id]）、flow、API、初始化、渲染等实现词汇；技术词仅允许出现在开发者可见的错误详情里。

**C. README 双语补「已知限制」一节**
真机证据两条，如实写进 README.md 与 README_CN.md（新增 Known Limitations / 已知限制 小节，放隐私边界之后）：
1. 视觉模型识别文字存在小概率错字（实测案例：同一张截图两次抽取，公司名"澄曜实验室"一次正确、一次识别为"潜曜实验室"）——确认卡片让用户过目正是为此设计，重要字段请留意核对；
2. 重复上传同一张截图会重复累积观测与会议（实测：同图三传后单联系人观测 22 条、日程出现两条相同会议）——当前版本不做自动去重，Future work 增加「同图检测与合并」条目。

**D. 互动记录摘要提炼**
现状：record_interaction 卡的 summary 是把原文句子用分号串联，不是提炼（真机上一张卡里塞了六段原文）。
修复：抽取/propose 相关 prompt 加一条："summary 用一到两句话提炼这次互动的要点（谁、聊了什么、有什么进展或情绪信号），不要罗列原文句子"。source_quote 保留原文职责不变。
单测不强求（prompt 行为），owner 真调验。

## Scope
`server/src/llm/prompts.ts`（A、D）+ app 内用户可见文案（B）+ 两份 README（C）+ A 的单测。不动其他业务逻辑、不动 fixtures、不新增依赖。

## Constraints
- 中文 commit message，自验全绿才 commit，一批一个 commit。
- B 项改文案不改布局与组件结构。
